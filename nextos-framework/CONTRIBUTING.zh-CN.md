# 为 NextOS 贡献

[English](CONTRIBUTING.zh-CN.md)

先阅读 [AGENTS.md](AGENTS.md)，选定要改进的契约，然后在自己的工作目录/分支中进行。在 NextOS 批准公开之前，仓库保持私有。

## 双语文档

在同一次变更中同步更新葡语与英语版本，包括链接、示例、命令、限制说明和数字。一份简短的英文概述不能替代完整指南的翻译。请把语言对登记到 [publication/languages.json](publication/languages.json)。

保持两个语言版本中的 API 标识符、路径、枚举和 schema 一致。只翻译解释性内容和提示语。使用已有的相对链接，并在给出命令之前先声明命令占位符。要区分「已测试的命令」与「仅核对过语法的命令」，以及「所依赖的 SDK/输入尚未提供因而只能作为配方」的情况。

不要覆盖已固定下来的历史翻译树。可以补充外部说明；保留哈希值、许可证文件和上游声明。规范性的法律文本保持原文；双语的许可说明不改变其条款。

## 合集与 Unity

合集包含由 NextOS 创建/整合的移植。对于公开仓库，要记录来源、提交和选源时使用的哈希。对于没有公开源码的社区分发，必须明确说明这一点，并且不要编造 URL 或快照。每个条目都需要有纳入授权和明确的证据范围。

`portando_unity` 只接受已收录的案例和经过审校的通用工具。不要复制包含其他游戏的本地索引、图库或指南。局部修复仍然保留其原有限制；它不会从同一标题的另一个构建版本中继承游戏流程。

## 代码与数据

V5 与参考源码保持原样保存。共享行为的变更另走 V6 的路线；新增一个适配器不会影响相邻的移植。专有数据要放在私有区域内，不要进入提交、issue 和 CI 产物。不要复述个人署名、设备地址、凭据或 APK 的下载来源。

对新代码使用定向测试。对文档类变更，请检查链接、命令一致性、措辞和引用完整性，而不要重建已通过评审的游戏。运行：

```sh
python3 publication/verify.py
python3 publication/verify-docs.py
git diff --check
```

## 提交与评审

合集署名写作 **NextOS**，并保留必需的第三方法律声明。切勿在提交中添加 AI 署名或共同作者信息。推送前请检查文件与提交信息。PR/提交需要说明结果、改动原因、验证方式以及实质性的限制。

发布游戏 ZIP 需要各自独立的[交付关卡](docs/zh/TESTING.md)。修订一份指南并不代表有权更改仓库可见性、迁移固定项或发布某个游戏版本。
