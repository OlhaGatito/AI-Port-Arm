# 图形、ETC1 与透明度

[English](../en/GRAPHICS-AND-TEXTURES.md) · [Português](../pt-BR/GRAFICOS-E-TEXTURAS.md) · [中文](#)

期望的结果是：在可用的物理上下文上呈现正确的画面。程序被翻译、上传无报错或帧率高，都不能替代这一证据。请保留每个端口已通过的图形路线。

## 1. 拆开四项决策

分别记录：数据中序列化的 API、可用的程序、Unity 请求执行的逻辑操作，以及设备上打开的物理上下文。门面可以把 GLES3 所需子集翻译成 GLES2，但不能在未实现其效果的前提下宣称具备该能力。

对于原生 GLES2 的 Unity，保留受支持的变体与格式。若构建使用其他程序，需逐一识别各阶段、参数、属性、采样器、常量与不兼容操作。编译链接后，比对真实场景。[Freedom Planet 2](FP2-VULKAN-GLES2.md) 说明了 Vulkan 程序为何需要专门的管线。

## 2. 测量常驻纹理

对每个对象记录：文件/容器 + 对象标识、尺寸、mip、原始/上传格式、消费方材质、实际 alpha、更新行为与生命周期。仅凭纹理名或孤立的 PathID 不足以在不同文件之间建立标识。

PNG 或压缩 bundle 衡量的是存储空间，不是显存。观察创建、重定义与删除；累计上传不等于同时常驻。要区分 CPU 副本、临时展开、编码器/缓存、GPU 载荷与驱动开销。

## 3. 按用途选择 ETC1/双平面

ETC1 以 4×4 块存储 RGB，每块八字节；alpha 需要另一种表示。依据 [Khronos ETC1 规范](https://registry.khronos.org/OpenGL/extensions/OES/OES_compressed_ETC1_RGB8_texture.txt)。双平面策略中，第二张压缩图承载 alpha，由着色器重建。

| 用途 | 初始决策 |
| --- | --- |
| 真正不透明的静态色块 | 评估 ETC1 RGB |
| 需要混合/切边的静态色块 | 评估双平面，并让着色器、采样器与 mip 保持一致 |
| 预乘色 | 保留 RGB/alpha 约定与混合方式 |
| SDF 字体、法线、LUT 或数值掩码 | 专门分析；不要归类为普通颜色 |
| 渲染目标、深度、视频或动态更新 | 不属于自动静态转换范围 |
| 用途/alpha 未知 | 转换前先调查 |

ETC1 不要求缩小尺寸。保留图集、矩形、UV、轴心与精灵。[Sally Face](../cases/zh/sallyface.md) 展示了裁切后的图集为何容易被误认为编码缺陷；[Horizon Chase](../cases/zh/horizonchase.md) 则保留了既有的 RGB/alpha 图层。

## 4. 计算字节数而不承诺帧率

对每个关卡，`ETC1 = ceil(w/4) × ceil(h/4) × 8`；累加每一个 mip，包括 2×2 与 1×1，它们仍各占一个块。双平面使用两个匹配的平面。极小的纹理可能节省为零。

在 1024×1024 且 mip 完整时：RGBA8888 为 5,592,404 字节载荷；ETC1 为 699,064；双平面为 1,398,128。这些是载荷计算值，不是实测 RSS 或驱动总分配。请使用[离线规划器](../diagnostico/texturas/zh/README.md)配合合成或本地清单。

## 5. 上传与着色器一并举证

观察完整定义、存储与子图像路径。仅拦截 TexImage2D 可能放行后续上传对纹理的扩展或覆盖。在无法证明块内容的前提下，ETC2 枚举不能变成 ETC1。保持格式/存储/上传三者一致。

双平面需校验 RGB/alpha 的对应性、尺寸、mip 与旁挂范围。相同 RGB 也可能有不同 alpha；不要选第一个匹配的 RGB 哈希。跟踪 GL 对象的重定义与删除。测量可用的纹理单元，并更新每一个必需的消费方程序。

保留着色器的 UV、过滤/环绕、预乘与切边阈值。检查边缘、小字号与远处 mip。[Merchant of the Skies](../cases/zh/merchantskies.md) 说明了 R8/alpha 通道契约必须同时尊重物理上下文与材质。

## 6. 分辨率与坐标

分别测量面板/可绘制区、窗口、渲染目标、逻辑视口与内容矩形。缩小窗口未必能缩小 RenderTextures。帧缓冲的虚拟分辨率可能大于可见区域。

处理黑边时，用内容矩形的偏移与缩放变换指针坐标；按契约处理在黑边区域的点击，而不是臆造有效位置。位置与增量必须共用同一原点与缩放。检查中心、四角、拖拽以及缩放后的释放。

不要对已通过的端口强加缩放策略。[Oceanhorn](../cases/zh/oceanhorn.md) 保留取景；[Prizefighters 2](../cases/zh/pf2.md) 需留意托管鼠标 Y 轴原点。

## 7. 完成改动

在固定工具与参数的事务性阶段转换所有者数据。比对未被触碰的对象，重新打开输出。然后在同一场景中测量质量、内存、加载时间与帧时间。理论上的减少不授权宣称帧率提升。
